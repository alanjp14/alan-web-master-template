# Repo map for agents

This is a **pnpm workspace monorepo**, not a single app.

| Path              | What it is                          | Runtime | Test    |
| ----------------- | ----------------------------------- | ------- | ------- |
| `apps/web`        | Next.js 16 App Router frontend      | Node    | Vitest  |
| `apps/api`        | Hono HTTP API                       | Bun     | `bun test` |
| `packages/shared` | Types + API contract, imported by both as `@app/shared` (raw `.ts`, no build) | — | — |

## Rules

- **`apps/web` tracks a fast-moving Next.js release.** Before writing
  framework code there, read the relevant guide under
  `apps/web/node_modules/next/dist/docs/` and heed
  [`apps/web/AGENTS.md`](apps/web/AGENTS.md) — it is regenerated by `next dev`
  and its guidance overrides stale training data.
- The web↔api boundary is typed through `packages/shared`. A change to a
  request/response shape goes there first; both apps must still pass
  `pnpm -r typecheck`.
- `apps/api` is Bun-only: use `Bun.env`, `bun test`, `bun build`. Do not add
  a Node server shim.
- Run from the repo root: `pnpm dev` (both apps), `pnpm -r lint`,
  `pnpm -r typecheck`, `pnpm -r test`, `pnpm build`. CI runs exactly these.
- Package manager is **pnpm** for the workspace; `bun` is the runtime for
  `apps/api` only. Never run `npm install`.

## Where things live

- Frontend conventions, folder standards, component rules: `docs/standards/`
